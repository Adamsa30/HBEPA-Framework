# Contributing to the HBEPA Reference Architecture Suite

Thank you for your interest in collaborating on the Home-Based Employment Preservation Accommodation (HBEPA) framework. This project operates at the intersection of disability-employment jurisprudence, zero-trust network engineering, and corporate human resource operations.

To preserve the foundational legal and architectural integrity of the system, all contributors must strictly adhere to the collaborative tracks and review guardrails detailed below.

---

## ⚖️ 1. Collaborative Contribution Tracks

To prevent the cross-contamination of technical code with clinical diagnostics or operational liabilities, contribution vectors are segregated into four distinct tracks:

### 📥 Track A: Disability Jurisprudence & Essential Functions Evolution
* **Focus:** Evolving ADA compliance models, case-law updates, and state-level reasonable accommodation tracking.
* **Asset Targets:** `legislative_brief_flsa.md`, `academic_abstract.md`, `.github/ISSUE_TEMPLATE/academic-clinic-feedback.md`
* **Rule:** Proposed changes must maintain the core philosophy of decoupling workforce connectivity and retention from active task performance or manufacturing output quotas.

### 🛡️ Track B: Cryptographic Gates & Network Privacy Engineering
* **Focus:** Hardening zero-trust edge authentication, upgrading mTLS 1.3 payload protocols, and auditing multi-factor hardware bindings.
* **Asset Targets:** `process_hbepa_validation_gate.py`, `process_hbepa_disconnect_handler.py`, `api_specification.md`, `data_flow_topology.md`
* **Rule:** Code updates must strictly enforce `Invasive_Surveillance_Bypass: True`. Any pull request that re-introduces peripheral tracking, geographic telemetry logs, keylogging, or video/audio capture endpoints will be summarily rejected.

### 📊 Track C: Relational Storage & Data Firewall Sanitization
* **Focus:** Optimizing PostgreSQL schema performance, refining database indexing bounds, and auditing role-based access control (RBAC) definitions.
* **Asset Targets:** `database_schema.sql`, `database_data_dictionary.md`
* **Rule:** The schema must maintain total diagnostic blindness. Under no circumstances may columns be appended that allow the transcription or storage of raw clinical text records, symptoms, or medical classifications.

### 🏢 Track D: HR Operations & Enterprise Governance
* **Focus:** Refining human-in-the-loop workflows, standardizing liaison manual operating procedures, and optimizing portal dashboard notices.
* **Asset Targets:** `enterprise_onboarding_checklist`, `ohl_operations_manual.md`, `management_dashboard_spec.md`, `portal_notifications.md`
* **Rule:** Dashboard layouts must preserve complete supervisory blindness, restricting management visibility exclusively to chronological state indicators (`Active`, `Idle`, `Paused`).

---

## 🛠️ 2. Pull Request & Code Review Requirements

All incoming pull requests (PRs) undergo a mandatory multi-disciplinary review process prior to compilation or main-branch integration:

1. **Static Analysis & Surveillance Check:** Automation suites check all Python files to verify that security parameters haven't been bypassed.
2. **The Principle of Transparency:** Contributors must sign off on the *Affirmation of Transparency Verification*: "I verify that these technical adjustments preserve the principle that the HBEPA model shall never be configured to manufacture, disguise, or false-certify evidence of productive work that was not performed."
3. **Redaction Validation:** Schema or API alterations must pass automated deep packet inspection checks to ensure medical data boundaries are strictly maintained under the HIPAA Minimum-Necessary rule.

---

## 📋 3. Code of Conduct & Academic Integrity

As an open-source public policy project, we expect all collaborators to maintain scannable, direct, and candid communication. We prioritize rapport, accessibility, and precision. Maintain architectural alignment, avoid dense prose walls, and format repository files cleanly to optimize readability for system auditors and clinical reviewers.
